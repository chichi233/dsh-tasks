# 任务权重评分口径 v1（已校准）

## 1. 一句话结论

公式 `score = round(100 × (0.40·work + 0.30·life + 0.20·urgency + 0.10·impact))`，权重按拍板口径未改；120 条人工标定后只调了档位边界，MAE 从 **20.05** 降到 **11.06**，偏差从 +15.73 收敛到 -0.51。

口径核对：未删除 **1294** 条 / 已删除 **430** 条 / 已打分 **1294** 条（Z == X 成立），其中未完成 95 条、已完成 1199 条（已完成同样打分，src 统一标 `calibrated`）。

## 3. 抽样标定

**分层方式**：清单 × 优先级共 17 个非空层（生日 p1、提醒 p1/p3 为空层），按层大小比例分配 120 个名额，最大余数法补差、每层至少 1 条，随机种子 `20261104`，抽样可复现。

**我的打分尺**（先定尺再逐条读，避免分数漂移）：

| 档 | 含义 |
|---|---|
| 80–100 | 硬期限 + 直接涉钱/合规/客户交付，拖了会出事 |
| 60–79 | 明确业务产出（设计稿、订单、投放），或硬性财务 |
| 40–59 | 有真实对象的事（约人、客户沟通、证照、采购），无强时限 |
| 20–39 | 生活杂事、素材/参考记录、习惯目标 |
| 0–19 | 标题无信息、纯占位、无动作的记忆碎片 |

**第一次核（v1，默认档位）：MAE 20.05 分**，bias **+15.73**（系统性高估）。原因很清楚：清单基线给得太高，任何任务只要落在收集箱就有 work 0.50 / life 0.40 打底，一条「天书奇谭」「闪电说」这种纯记忆碎片也能拿 36 分；同时强工作任务的 work 封顶只有 base+0.30，合规任务反而被低估。

**调整动作**（只动档位边界与基线，0.40/0.30/0.20/0.10 一个字没改）：

1. 清单基线从「0.3–0.8 的分类主依据」降为「0.04–0.28 的弱先验」，改由标题词主导；
2. 关键词三分档：硬信号（钱/合规/客户）+0.75、业务创作 +0.40、无信号压到 0.12；
3. 生活分拆「家人/生日 +0.45」与「杂事 +0.25 且封顶 0.45」，避免把「理发」和「大姨生日」算成同一档；
4. 加订单识别：标题含 3 位以上数字且正文出现「定/报/价/款/单」→ 按 +0.65 处理（`陈星 + 新中式 30 1200 定600` 这类）；
5. 灵感/无动作类（笔记、心法、灵感、练习）work≤0.18、life≤0.12。

## 7. 插件现算版（heuristic，纯 JS，不依赖模型）

新任务没有历史分，用同一套规则现算即可：档位、词表、基线都与 `tt-scores.json` 的 Python 实现逐条对齐，同一任务两边应得同分（改词表时需同步两处）。

```js
const HARD = ['信用卡','还款','花呗','房租','收租','报税','税','发票','报销','年审','年检',
  '营业执照','工商','合同','客户','定金','尾款','报价','结算','工资','社保','交强险','保险',
  '续费','网费','服务器','到期','面试','招聘','交付','对账','上线','汇报','评审','复盘','稿费',
  '投放','驾照','驾驶证','车牌','账'];
const BIZ = ['设计','手稿','出稿','素材','拍摄','剪辑','排版','插画','纹身','模特','视频',
  '小红书','运营','账号','打印','测试','项目','工作室','采购','定制','亚克力','耗材','安装',
  '封面','文案','选题'];
const FAM = ['生日','🎂','大姨','干妈','妈妈','爸爸','老婆','雅','孩子','陪','家里','送',
  '接人','见面','见','约饭','聚餐','还礼','红包','送礼'];
const CHORE = ['理发','洗车','洗头','早睡','快递','取件','退货','退','买','补鞋','剪指甲',
  '猫','狗','鱼缸','换水','火锅','吃饭','拖鞋','蚊帐','净水器','螺丝','内存条','尺寸','测量',
  '储物间','射灯','窗帘','镜子','风扇','包装袋','计时器','闲鱼','存钱','读书'];
const IDEA = ['灵感','心法','习惯','理论','构思','主题','想法','练习','阅读','笔记','整理',
  '参考','思路','流程','尝试','实验'];
const WORK_BASE = {收集箱:.10, 今日要事:.22, 生日:.04, 提醒:.10, 艺术:.15};
const LIFE_BASE = {收集箱:.10, 今日要事:.08, 生日:.28, 提醒:.20, 艺术:.10};
function has(s, arr) { const h = arr.filter(k => s.includes(k)); return h; }
export function scoreTask(t, today = new Date()) {
  const body = (t.title || '') + '\n' + (t.content || '');
  const hard = has(body, HARD), biz = has(body, BIZ);
  const fam = has(body, FAM), chore = has(body, CHORE), idea = has(body, IDEA);
  const order = /\d{3,}/.test(t.title || '') && /[定报价款单]/.test(body);
  let work = WORK_BASE[t.projectName] ?? .10;
  if (hard.length) work += .75; else if (order) work += .65; else if (biz.length) work += .40;
  if (new Set([...hard, ...biz]).size >= 2) work += .08;
  let life = LIFE_BASE[t.projectName] ?? .10;
  if (fam.length) life += fam.length >= 2 ? .53 : .45;
  else if (chore.length) life = Math.min(life + .25, .45);
  if (!hard.length && !biz.length && !fam.length && !chore.length) {
    work = Math.min(work, idea.length ? .18 : .12);
    life = Math.min(life, idea.length ? .12 : .10);
  }
  work = Math.min(1, Math.max(0, work)); life = Math.min(1, Math.max(0, life));
  let imp = 0;
  if (t.hasChildren) imp += .3;
  if (t.repeat) imp += .2;
  if ((t.content || '').trim().length > 80) imp += .2;
  if (hard.length || fam.length) imp += .3; else if (biz.length || order) imp += .15;
  imp = Math.min(1, imp);
  let urg = .2;
  if (t.date) {
    const d = Math.round((new Date(t.date.slice(0, 10)) - new Date(today.toISOString().slice(0, 10))) / 864e5);
    urg = d < 0 ? 1 : d === 0 ? .95 : d <= 3 ? .8 : d <= 7 ? .6 : .35;
  }
  return Math.round(100 * (.40 * work + .30 * life + .20 * urg + .10 * imp));
}
```

调用约定：`projectName` 传清单名（收集箱/今日要事/生日/提醒/艺术🎨art），`hasChildren` 传「是否存在 parentId 指向本任务」的布尔值，`repeat` 传原样的 RRULE 字符串或 null。排序时同分用 `priority` 降序、再按 `date` 升序打破平局——**公式没用 priority，但排序可以用它**，这是本数据集里唯一还没被利用的人工信号。
